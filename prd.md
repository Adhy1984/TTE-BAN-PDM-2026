ZONA ATAS: SPESIFIKASI KEBUTUHAN PRODUK (SYSTEM BLUEPRINT)
================================================================================

## 1. Nama Projek & Problem Statement
- **Nama Aplikasi:** e-TTE Signature Portal (Aplikasi TTE Surat BAN PDM Prov. NTT)
- **Problem Statement:** 
  Proses penandatanganan surat resmi secara manual/basah memakan waktu, rentan terhadap keterlambatan saat pejabat bertugas di luar kantor, serta sulit diverifikasi keasliannya secara publik. Sistem ini menyediakan platform digital terpadu untuk penyusunan, pengesahan, pembubuhan QR-Code TTE pada dokumen PDF, dan verifikasi keabsahan dokumen secara real-time.

## 2. Peran Pengguna (User Roles)
1. **Admin / Koordinator:**
   - Memiliki hak akses penuh ke seluruh menu.
   - Mengelola data master pengguna, profil pejabat, pengaturan instansi, dan log sistem.
2. **Operator / Staf:**
   - Menyusun draf surat resmi, memilih template, dan mengisi variabel surat.
   - Mengunggah lampiran PDF dan mengajukan surat ke pejabat penandatangan.
   - Memantau status proses pengesahan.
3. **Pejabat Penandatangan:**
   - Menerima notifikasi/antrean draf surat yang diajukan.
   - Memeriksa isi dokumen dan menyetujui atau menolak dengan catatan.
   - Melakukan penandatanganan elektronik resmi (TTE) dengan verifikasi PIN rahasia 6-digit.
4. **Publik / Pihak Ketiga (Tanpa Login):**
   - Memindai QR-Code yang tertera pada dokumen surat PDF.
   - Mengakses portal verifikasi publik (`?p=verify&id=DOC-XXX`) untuk membuktikan keaslian dokumen secara instan.

## 3. Arsitektur & Lingkungan Kerja
- **Platform Backend:** Google Apps Script (V8 Runtime) - Standar Controller/Service Terpisah.
- **Database:** Google Spreadsheet terpusat (ID: `1Vgz-BTW3Mx-veAWfeDST4IAm9XUWldXW6_wSWvY8BGY`).
- **Penyimpanan Berkas:** Google Drive Folder Resmi (ID: `1-sdC6uaHqA88CT4U4YdgWgpTsYpYeys_`).
- **Frontend Engine:** HTML5, CSS3 kustom (Anti-AI Human-Crafted Aesthetic), Vanilla JavaScript modular.
- **Library Klien:**
  - `pdf.js` (v3.11.174): Render dan visualisasi dokumen PDF di browser.
  - `pdf-lib` (v1.17.1): Pembubuhan stempel dan QR-Code langsung ke dalam lembar PDF.
  - `qrserver.com API`: Pembangkit grafis QR-Code dinamis beresolusi tinggi.

## 4. Alur Kerja Aplikasi (End-to-End User Flow)
1. **Autentikasi:** Pengguna masuk melalui halaman login dengan username & password.
2. **Dashboard:** Pengguna disajikan ringkasan statistik (Total Surat, Draft, Menunggu TTE, Ditandatangani, Ditolak).
3. **Pembuatan Surat:** Operator membuat surat baru atau memilih template (Surat Tugas, Surat Undangan, Nota Dinas, dsb.).
4. **Pengajuan Dokumen:** Operator submit surat -> status berubah menjadi `MENUNGGU_TTD`.
5. **Review & TTE Pejabat:** Pejabat memeriksa dokumen -> memasukkan PIN TTE 6 digit -> sistem membubuhkan QR-Code verifikasi dan stempel resmi ke PDF -> status berubah menjadi `DITANDATANGANI`.
6. **Verifikasi Publik:** Publik memindai QR Code pada PDF -> membuka URL verifikasi -> sistem menampilkan status keaslian dokumen, penandatangan, dan riwayat penerbitan.

## 5. Desain Basis Data (Google Sheets)
1. **Tab `users`:** ID User, Username, Password, Nama, Role (admin/operator/pejabat), Status (AKTIF/NON-AKTIF), Pejabat ID.
2. **Tab `pejabat`:** ID Pejabat, Nama Lengkap, NIP, Jabatan, PIN TTE (Hashed/Protected), Status TTE.
3. **Tab `surat`:** ID Dokumen, Nomor Surat, Perihal, Tanggal Surat, Kategori, Pejabat ID, Status, File PDF ID, Tgl TTE, Log Audit.
4. **Tab `log_verifikasi`:** ID Log, Doc ID, Waktu Scan, IP / User Agent, Status Hasil.
5. **Tab `pengaturan`:** Parameter konfigurasi sistem (Kop Surat, Logo, Kontak, Footer).

## 6. Aturan Validasi & Logika Keamanan
- Autentikasi sesi menggunakan Server-Side Session Token acak (UUID) yang tersimpan di CacheService Google Apps Script dengan batas kedaluwarsa maksimal 10 menit dan Idle Auto-Logout Timer peramban (10 menit tanpa aktivitas).
- Validasi PIN TTE Pejabat di layer backend sebelum memproses penandatanganan.
- Sanitasi input form dan proteksi `event.preventDefault()` pada seluruh form submit.
- Nilai penanggalan menggunakan zona waktu resmi `Asia/Jakarta` (`GMT+7`).
- Failure handler pada setiap pemanggilan `google.script.run`.

## 7. Rencana Antarmuka (Modular Views)
- `Index.html`: Shell utama aplikasi, routing query params, modal overlay, dan container toast.
- `AuthView.html`: Halaman login sistem (Split-screen modern, branding BAN PDM, kredensial).
- `DashboardView.html`: Ringkasan metrik statistik operasional.
- `SuratView.html`: Form pembuatan dan editor surat dinamis.
- `DaftarSuratView.html`: Tabel arsip dan manajemen status dokumen.
- `SignView.html`: Antarmuka preview & penandatanganan dokumen oleh pejabat.
- `VerifyView.html`: Portal publik verifikasi keabsahan dokumen via pemindaian QR-Code.
- `Styles.html` & `Scripts.html`: Desain terpusat dan logika interaksi klien.
